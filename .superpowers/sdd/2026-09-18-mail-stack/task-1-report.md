## Implementation Details

The `config.ts` module provides:

- **Config type**: Complete configuration object with:
  - `mailDomain` and derived `mailHostname` (prefixed with "mail.")
  - Required fields: `forwardTo`, `cfApiToken`, `cfZoneId`, `dmarcRua`
  - Optional fields: `deliveryTargets` (defaults to ['forward']), `dkimSelector` (defaults to 'mail')
  - Conditional `relay` field (null when RELAY_HOST is empty)

- **RelayConfig type**: SMTP relay configuration with host, port, user, password, and SPF include

- **ConfigError class**: Custom error that collects all validation failures at once

- **loadConfig() function**: Validates environment variables, applies defaults, and enforces constraints:
  - Domain validation using regex pattern
  - Relay configuration requires RELAY_SPF_INCLUDE when RELAY_HOST is set
  - Collects all failures before throwing

## Key Design Decisions

- Never hardcodes `dev.horizons.gg` or `mail.dev.horizons.gg` in code; both derive from `MAIL_DOMAIN`
- Validation is fail-fast as a whole (all failures collected), but individual fields only required if context warrants
- Relay SMTP port defaults to 587 if not specified
- Domain names validated using lowercase alphanumeric with hyphens (no leading/trailing hyphens)

## Fix Report: RELAY_PORT Validation

### Issue

The original implementation silently produced `NaN` for invalid `RELAY_PORT` values (e.g. "abc", "70000", or whitespace-only). This violated the module's stated purpose of being a validation gate that catches all configuration errors before startup.

### Changes Made

Modified `mail/mailops/src/config.ts` (lines 55-69):
- Added explicit port validation that only applies the default of 587 when the env var is unset or empty
- For non-empty RELAY_PORT values, validate that they are finite numbers in the range 1-65535
- Push failure message "RELAY_PORT must be a number between 1 and 65535" for invalid values
- Does not produce a failure when port is unset (default 587 still applies)

Added 4 new test cases to `mail/mailops/src/config.test.ts`:
- "defaults to port 587 when RELAY_PORT is unset": Verifies default behavior without failure
- "rejects a non-numeric RELAY_PORT": Verifies "abc" produces the error
- "rejects RELAY_PORT out of range (too high)": Verifies 70000 produces the error
- "rejects RELAY_PORT out of range (zero)": Verifies 0 produces the error
